# Android 因子アシスト（試作）

ウマ娘の因子継承画面をAndroidの画面共有で読み取り、登録したプリセットと照合して
必須／重要／必要の因子を数えるアプリ。PC版とは独立して動作する。Android 14以上を対象とする。

## 操作

- アプリでプリセットを作成するか、PC版の共有コード・コードファイル・保存したQR画像を取り込む。
- プリセット編集は因子の一覧から選んで追加する。検索窓で絞り込める。
- プリセットの書き出しは共有コード・コードファイル・QR画像（分割対応）の3通り。
- QR画像の取り込みは複数選択可能。分割QRは同じ更新の全画像を取り込む。カメラ直接スキャンは未実装。
- フローティング表示を許可してボタンを表示する。
- 「☰」でプリセット選択・編集・表示設定。隣の「開始」は認識中「終了」に変わる。
- 開始するとゲームを起動し、画面共有の確認は1回で済む。画面全体ではなくゲームのアプリ単体を選ぶ。
- 簡易結果・メニューボタン・動作状況はそれぞれ別ウィンドウで、個別にドラッグできる。
- 簡易結果は元因子・再獲得因子の必須／重要／必要の個数のみ。タップすると詳細に因子名・星数が出る。
- 詳細の並び順はゲーム画面と同じ（上から下）。下から上にスクロールして読んでも順番は変わらない。
- 設定で因子枠の表示を切り替えられる。認識した行を画面上に重ねて描く（不透明度0.75、スクロール中も追従）。
- 表示設定は文字サイズ・文字色・縁取り・背景色・背景の不透明度。すべて端末に保存する。
- 設定の「毎秒の認識目標回数」は初期値5。正の整数で自由入力できる。15程度で十分な精度が出る。
- 推論スレッドは「自動」が既定。端末のコア数に合わせて選び直すこともできる。
- 動作状況に直近5秒・60秒の実測サイクル数、平均処理時間、段階別の内訳を表示する。
- 実測は画面判定を含む完了処理の回数で、認識成功件数ではない。取得や推論が間に合わないときは最新フレームのみ処理する。
- 見出しと因子の位置が端末で合わない場合は、スクリーンショットから位置合わせできる。
- 横画面などでメニューが画面外に出た場合は、通知から呼び戻せる。
- フローティング全体の終了はメニューまたは通知から。再表示はアプリ本体から。
- 設定とプリセットは端末に保存され、アプリを更新しても残る。

## 認識の仕組みと制限

因子名・星数にはPC版と同じumacaptureの専用ONNXモデルを使用。ライセンスはassetsに同梱。
金色の星から行位置を検出して切り出す。見出しのみML Kit日本語OCRを使用し、
見出しの文字の形を覚えたあとは同じページの間OCRを省く。
見出しと因子名・星数が2回続けて認識された結果を元因子・再獲得因子1〜9に蓄積する。
ページ切り替え中（見出しか星の列が動いている間）のフレームは採用しないので、
前のページの因子が次のページに混ざらない。
名前・星数の確信度が低い場合は採用しない。高速スクロール時は取りこぼす可能性がある。
最低星数に届かない登録因子は「条件未達」へ分け、必須／重要／必要の個数には含めない。
スキル取得画面の認識は未実装。縦画面を主対象とする。
結果は停止しても保持、明示リセットで消去するがアプリプロセス終了では消える。

## 因子データの更新

`assets` の `factor.onnx` `factor_rank.onnx` `labels.json` `factor_info.json` `factor_tag.json` は
[umasagashi/umacapture](https://github.com/umasagashi/umacapture) のモジュールから取得している。
因子が追加されたときは、PCの umacapture がモジュールを更新したあとに
`powershell -ExecutionPolicy Bypass -File update-modules.ps1` を実行する
（既定の取得元は `%APPDATA%\umasagashi\umacapture\modules`）。

ライセンスは同梱の [assets/umacapture-modules-LICENSE.md](app/src/main/assets/umacapture-modules-LICENSE.md)
および [assets/umacapture-LICENSE.txt](app/src/main/assets/umacapture-LICENSE.txt)（MIT）が原文。要点は次のとおり。

- `factor.onnx` / `factor_rank.onnx` … umacapture 作者が一から作成した学習済みモデルで、**パブリックドメイン**。
  表記・許可・報告のいずれも不要とされている。
- `labels.json` / `factor_info.json` / `factor_tag.json` … **ウマ娘のゲーム内テキスト（株式会社Cygamesの著作物、
  一部は登録商標）を含む**。umacapture 作者はこれらの部分に権利を主張しておらず、ライセンスは原権利者の裁量による。
  本リポジトリもこれらの部分について何ら権利を主張しない。

このアプリはファン制作の非公式ツールであり、株式会社Cygamesおよび umacapture とは関係がない。

## ビルドと署名

JDK 17以上、Gradle 9.3.1、Android SDK platform 35。`ANDROID_HOME` を設定して

    gradle :app:assembleRelease :app:testDebugUnitTest

生成物は `app/build/outputs/apk/release/app-release.apk`。
デバッグビルドはARTの最適化が弱く、推論が数倍遅くなるため、速度を見るときはリリースビルドを使う。
このWindows環境では日本語パスでGradleのテストクラス読込が失敗するため、一時的なASCIIパスで検証している。
デバッグ署名は同じPCの通常の `debug.keystore` を利用する。別の署名鍵では上書きインストールできない。
継続利用版は専用鍵を用意し、同じapplicationIdと署名鍵を維持してversionCodeを上げる。
秘密鍵はリポジトリに入れない。
